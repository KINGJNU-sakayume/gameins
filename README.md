# CLAIM DENIED: 사건 #001~#005 프로토타입

`docs/02_CLAIM_DENIED_사건설계_001_002.md`의 두 사건과 `docs/03_CLAIM_DENIED_사건설계_003_초안.md`(요약 기반 초안)의 #003, `docs/04_CLAIM_DENIED_사건설계_004_005.md`의 #004·#005를 실제로 플레이해 보는 정적 HTML 프로토타입입니다. 뒤로 갈수록 판정 요소와 서류 종류가 늘어납니다: #003 항목별 판정, #004 기각 사유(첫 기각 정답 사건), #005 항목별 인정액(감액). 설계서의 '다음 단계' 1·2번(증거 열람 → 근거 고정 → 판정 제출 → 해설, `undermines`/`corroborates`, 보류, 1일 지연 자료 요청)을 검증합니다.

## 실행

빌드 단계가 없습니다. `prototype/` 폴더를 정적 서버로 엽니다.

```sh
cd prototype && python3 -m http.server 8000
# http://localhost:8000
```

진행 상황(서류 위치 포함)은 브라우저 localStorage에 저장됩니다. 결과 쪽지의 "이 사건 다시 하기"로 사건을 처음 상태로 돌립니다.

## 화면

책상 위에 사건 서류가 겹쳐 쌓여 있고, 오른쪽에 판정서가 고정돼 있습니다.

- 서류를 끌어 옮기고 나란히 놓아 대조합니다. 누른 서류가 맨 위로 옵니다. 키보드: 서류에 초점, 화살표로 이동(Shift는 크게), Enter로 맨 위.
- 서류를 판정서 위로 끌어 놓거나 서류의 "판정서에 첨부"를 누르면 근거로 첨부됩니다. 첨부한 서류는 더미 맨 아래로 내려갑니다.
- "가지런히"는 겹친 더미를 평평하게 펼칩니다.
- 아래 서류함에서 조사하면 새 서류가 책상으로 옵니다. 하루 늦게 오는 자료는 봉투로 기다립니다.
- 반박 자료가 책상에 오르면 약해진 서류에 "불일치" 꼬리표가 붙습니다.
- 제출하면 판정서에 도장이 찍히고 결과 쪽지가 책상에 놓입니다. 위쪽 번호표로 사건을 오갑니다.
- 기각을 고르면 판정서에 기각 사유를 고릅니다. #005는 보장 항목마다 인정액을 적습니다.
- 60rem 미만 화면에서는 끌기 대신 서류를 세로로 펼칩니다.

## 서류 종류

출처가 다른 서류는 종이도 다릅니다. 청구서(연녹색 회사 양식), 계약서(겹줄 테두리), 사진 기록(마닐라지), 견적서·명세서·세금계산서, 영수증(감열지), 진술·메모(노란 메모지), 시스템 기록(감열지 롤), 감정 보고(검은 머리띠)에 더해 #004·#005에서 다음이 나옵니다.

- **공문** (경찰 신고 접수증, 수사 회신, 소방서 조사서): 겹선 테두리와 붉은 관인. 관인은 출처를 나타낼 뿐 판정 힌트가 아닙니다.
- **통화 녹취록**: 시각, 화자, 발언 세 칸.
- **메신저 대화 캡처**: 휴대폰 화면 인쇄본. 보낸 쪽은 오른쪽 정렬과 테두리, 받은 쪽은 왼쪽 정렬과 채움으로 구분합니다.
- **신문 기사 스크랩**: 오려 낸 가장자리와 두 단 본문.

## 디자인

[Hallmark](https://github.com/Nutlope/hallmark) 스킬의 app screen 범위로 만들었습니다. 테마는 Formwork(콘크리트 회색, 검정 잉크, 각진 모서리, 하드 섀도, 안전 주황 한 가지)에 책상 면과 종이 종류 토큰을 더했습니다. 3열 업무 화면, 기울인 서류 더미, 기울이지 않은 서류 더미를 비교한 뒤 마지막 안을 골랐습니다. `sloplint --scope app` 결과 FAIL 0입니다.

## 배포 (GitHub Pages)

`.github/workflows/pages.yml`이 `main`에 `prototype/` 변경이 들어오면 사건 데이터 검증을 돌린 뒤 GitHub Pages로 배포합니다. Actions 탭에서 수동 실행(workflow_dispatch)도 됩니다.

처음 한 번만 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 바꿔야 합니다. 바꾸기 전에는 배포 단계가 실패합니다.
